1 · 一句话定位

一个把营销方法论封装成确定性工具的本地工作台。

拆解这句定位，它同时回答了三件事：

  • 完整决策链 —— 不是工具集合，是有方向的一条链。品牌是输入、营销是输出、复盘是回写。
  • 确定性 —— 能算的不交给模型。每个建议都能回答"凭什么这么建议"。
  • 本地运行 —— 数据不出浏览器，联网默认关闭、由用户自主开启。
为什么是"品牌 → 增长"而不是"营销工具箱"

品牌和营销不是两件事，是一条链的两端：品牌是输入，营销是输出，复盘是回写。缺任何一段，链就断了——没有品牌内核，营销就是"什么火蹭什么"；没有营销执行，品牌只是文档里的三句话；没有复盘回写，市场变了品牌还停在原地。

这条链的关键接缝在「品牌内核 → 内容生成」：品牌算出来的调性、价值主张、品类禁忌，必须真正约束内容生产。这一处焊死后，"品牌驱动营销"才从说法变成事实。

3 · 边界：做与不做

这个产品的价值，一半在做了什么，一半在明确拒绝做什么。

不做（附硬理由）

不做理由
自动抓取竞品/热点数据CORS 硬限制，且会破坏"数据不出浏览器"的隐私承诺
引入 ECharts / Three.js会击穿"零依赖 + 单文件"；已手写 25 种骨架替代
设计功能（画 Logo / 排版）要么拖进重型依赖，要么只能做出玩具；改做资产台账
定时提醒页面关闭 JS 就停，不假装能做到
后端 / 账号 / 云同步与本地定位根本冲突
LLM 意图识别（方案二）现阶段规则够用，引入只会增加延迟与不确定性
内嵌 Python（Pyodide）30MB+，摧毁单文件；改做导出接口

改做（因为做不到/不该做，所以换了实现）

  • 热点"求真" → "该不该跟"：做不到事实核查，改做决策判断
  • 竞品自动监测 → 人工台账：诚实标注需手动录入
  • 内容包付费 → 全免费：调用的是已有本地函数，无边际成本；付费与"核心功能永久免费"冲突
  • Excel/Python 集成 → 接口定义：不做在线 Excel，只定义 CSV 进出与 JSON 规范

存储层
localStorage 单一 state，全量备份/恢复 .json
关于"是不是 Agent"

按 Anthropic《Building Effective Agents》的划分：Workflow 是"LLM 与工具按预定义路径编排"，Agent 是"LLM 动态决定流程与工具"。本产品属于 Workflow，且是人工预定义的路径。

这不是缺陷——那篇文章的核心观点恰恰是能 workflow 就别 agent。营销结论要交付给客户，不能让模型自由发挥。所以能算的都做成确定性函数，只把创作类交给模型，LLM 步骤采用 Human-in-the-loop（人工回填后续跑）。

6 · 核心算法

28 个确定性函数，全部可用手算验证。选几个代表性的：

品牌内核：位置型 vs 强度型维度

关键设计——价格定位是位置型维度，无好坏只有选择。星巴克在溢价端不是缺点，是选择。所以主战场识别看相对品类基准的偏离，而非绝对分：

主战场   = 绝对分 ≥ 4.0（下了重注）
差异化   = 相对基准偏离 ≥ 0.5
撕裂检测 = 预置矛盾对（溢价↔高频折扣、稀缺↔全渠道铺货…）

验证：星巴克、瑞幸、香奈儿、DIOR 四个案例全部判定"自洽且有记忆点"——它们只是选了不同主战场。而"奢侈品 + 高频折扣"的反例能正确检出冲突。它不评判哪个更好，只判断有没有前后矛盾。

调性约束：同一文案、不同品牌、不同结论

文案："限时秒杀！全场最低价！赶紧冲！！！"

香奈儿（奢侈品·克制·溢价）→ 0 分，触犯品类禁忌
瑞幸（性价比·效率）      → 通过

6 个可量化信号：感叹号密度、emoji 密度、绝对化用词、促销词、第二人称频率、平均句长。禁忌表是条件启用的——"秒杀"对溢价端是硬命中，对性价比端不触发。禁忌跟着定位走，不跟品类走。

洞察回归：样本不足就不给趋势

if (n < 5) return '样本不足（'+n+'/5），趋势暂不可判断';

对 3 个点做最小二乘也能算出斜率，但那是噪声不是结论。宁可少说，也不说一个自己都不信的数字。

内容包：本地函数优先

重新编排后，小红书包 6 步中 4 步是真跑（品牌内核→体检→调性→排期）。跑完即有真实数字，结果页图表才有依据。AI 产出是自由文本，不包装成图表。

品牌轨迹：把隐性的记录层显性化

产品里原本散落着 7 处记录（营销动作、竞品动态、内容评分、战略快照、执行 Trace、生成留痕、对话），用户要打开 7 个模块才能拼出完整轨迹。品牌轨迹把它们提取成一个统一时间线——不增加新能力，只是把隐性的显性化。

难点是 4 种时间格式归一（YYYY-MM-DD、YYYY/M/D H:M:S、ISO、纯时分秒）。对话历史只存了 HH:MM:SS 无日期，技术上无法恢复，故旧记录标为"日期未知"排在最后，不假装发生在今天。

8 · 数据设计

  • 单一 state：全部状态挂在一个对象，序列化即全量备份
  • 存储分类：设置页按知识库/工作台/内容评分/策略档案/其他分类显示占用，UTF-16 计字节
  • 有上限的：history 50 条、chat 60 条、scores 100 条
  • 无上限但有软提醒：知识库单篇 >5 万字提示（不阻止，用户有权存）
  • 备份：全量导出/恢复 .json —— 这是"数据不出浏览器"承诺的必需配套，否则本地存储会退化成"丢了就找不回"

9 · 设计决策

为什么 70 个框架只配 25 种骨架

营销框架的图形结构只有 25 种（四象限、九宫格、雷达、漏斗、金字塔…）。所以每个框架配置只一行：

'S-02': {s:'radar', t:'五边形雷达图',
         l:['供应商议价','购买者议价','新进入者','替代品','同业竞争']}

750 行引擎覆盖全部 70 个，而不是写 70 套渲染器。

为什么"未实现"的框架不是灰按钮

39 个方法论速查卡片，点开显示"看什么 / 输出什么 / 常见误用"。比如 PEST 的常见误用：把 PEST 写成新闻剪报——每格堆事实，却不写对我们的具体影响。从"61 个空壳"变成"70 个方法论速查"，后者本身就有价值。

为什么色彩一致性只做软提示

色彩心理学是经验共识，不是硬科学，没法像 LTV 那样验算。所以只说"可能存在张力"，标注"非精确科学，仅供参考"，绝不说"你错了"。

为什么对话式采集只管启动前

内容包中间步骤是"用户去 LLM 跑完粘回来"，粘的是几百字正文——用疑问句/黑名单判断它对不对没有意义。所以规则只管采集，不管粘贴；粘贴步骤改用"可复制提示词 + 字数提示"。

11 · 已知问题

  • 知识库检索是关键词匹配，非语义检索
  • 竞品与热点需手动录入，无自动抓取（技术限制，已在界面标注）
  • 对话历史缺日期，旧记录无法恢复时间，标为"日期未知"
  • 部分框架图标注曾与实际骨架不一致，已统一；新增框架时需同步核对
  • 工作流 LLM 步骤需人工回填，属 Human-in-the-loop 设计，非缺陷但需说明

12 · 面试线索

三个最有说服力的讲点
  1. 把最后一个无计算逻辑的模块重构成了确定性工具 —— 品牌人格原本只是选个 MBTI 让模型发挥，重构成三层结构 + 五类诊断后，现在产品里没有"纯 prompt 拼接"的模块。
  2. 边界感：8 条明确不做 —— 自动抓取、ECharts、设计功能、定时提醒、后端、LLM 意图识别、内嵌 Python、内容包付费。每条都有硬理由。
  3. 诚实处理做不到的事 —— 样本不足不给趋势、对话历史缺日期就标"未知"、竞品手动录入如实标注、色彩只做软提示。不假装能做到。

如果被追问"为什么不做成真 Agent"

营销方案的结论要交付给客户，不能让模型自由发挥。所以能算的都做成确定性函数，只把创作类交给模型，LLM 步骤采用 Human-in-the-loop。这是准确性优先于自主性的取舍。

如果被追问"这 20 多个模块不就是堆功能吗"

看两点：一是有入口层（流程导航 + 对话路由 + 内容包窗口）重新组织了使用路径；二是模块间真的咬合——品牌内核算出的调性会约束内容体检，战略矩阵的任务会带来源地推到日历，7 处记录会汇成一条品牌轨迹。
